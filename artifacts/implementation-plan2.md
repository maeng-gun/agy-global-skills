# Antigravity 2.0 Agent Specification: Notion Uploader Skill

## 1. System Persona & Goal (작업 컨텍스트 문서)
- **에이전트 역할 및 목적:** 프로젝트 내 존재하는 Markdown(.md) 또는 일반 텍스트(.txt) 파일을 노션 API 규격에 맞게 구조화하여 지정된 노션 데이터베이스에 새 페이지로 자동 발행(Publish)하는 범용(General) 글로벌 스킬.
- **배경 및 범위:** 
  - 에이전트가 수행한 특정 작업(리서치, 요약, 기획 등)의 산출물을 노션에 영구적으로 기록하고 보관하기 위함.
  - 타겟 DB: 'Mater DB' (Data Source ID: `3bcbad03-f76c-80c3-b81c-000b6bd3509a`).
  - 생성되는 페이지는 기본 속성으로 동적 '이름(LLM이 판단)', '읽음상태(안읽음)', '구분(AI 생성)'을 반드시 포함해야 함.
- **주요 제약조건:** 
  - 노션 API의 엄격한 길이 및 블록 제한(단일 텍스트 블록 최대 2,000자, 1회 요청 시 하위 블록 최대 100개)을 우회할 수 있는 파이썬 스크립트 단의 자동 청킹(Chunking) 로직 필수.
  - 범용 스킬로서 어떠한 프로젝트에서 실행되더라도 현재 작업 중인 가상 환경(venv 등)을 오염시키지 않도록, `uv run`과 인라인 메타데이터(PEP 723)를 통한 완벽한 샌드박스 격리 필수.
  - 인증 토큰(`NOTION_API_KEY`)은 스킬 폴더 내에 하드코딩하지 않고, 스킬이 실행되는 타겟 프로젝트의 로컬 `.env` 파일에서 동적으로 로드해야 함.

## 2. Triggers & Data Flow (트리거 및 데이터 흐름)
- **Input (입력):** 
  - 사용자의 명시적인 업로드 지시 프롬프트 (예: "결과물을 노션에 업로드해 줘") 또는 에이전트의 이전 작업으로 산출된 텍스트/마크다운 파일.
- **Output (출력 및 임시 데이터):** 
  - **최종 산출물:** 노션 'Mater DB'에 성공적으로 생성된 새 페이지의 URL (터미널 출력).
  - **임시 데이터 (반드시 작업 중인 프로젝트의 `scratch/` 폴더 사용 후 폐기):** 
    - `scratch/notion_upload_temp.md`: LLM이 구조를 최적화(이모지, 표, 강조 등)하여 작성한 마크다운 파일.
    - `scratch/notion_upload_meta.json`: 페이지 제목과 기본 속성이 정의된 메타데이터 파일.

## 3. Core Workflow (워크플로우 정의 및 로직 분리)
> **설계 원칙:** Antigravity 2.0 에이전트의 네이티브 도구를 최대한 활용하여 에이전트가 직접 수행하도록 설계하며, 에이전트가 처리하기 지나치게 복잡한 결정론적 연산(API 통신 및 데이터 청킹)에 한해서만 파이썬 스크립트로 위임합니다.

- **Step 1: 콘텐츠 가공 및 임시 파일 구조화**
  - **역할 주체:** 메인 에이전트 (직접 수행)
  - **로직 설명:** 원본 문서의 내용을 분석하여 노션에 적합한 제목을 결정합니다. 내용은 이모지, 표, 강조 등 다양한 블록 객체로 변환하기 쉽도록 구조화된 마크다운으로 포맷팅합니다. 가공된 본문은 `scratch/notion_upload_temp.md`에, 생성된 제목과 고정 속성(읽음상태, 구분)은 `scratch/notion_upload_meta.json`에 저장합니다.
  - **성공 기준 및 예외 처리:** `scratch/` 디렉토리에 두 개의 파일이 정상적으로 생성되었는지 파일시스템 도구를 통해 검증합니다.
- **Step 2: 업로드 샌드박스 스크립트 실행**
  - **역할 주체:** 메인 에이전트 (스크립트 실행)
  - **로직 설명:** 터미널 명령어를 통해 글로벌 스킬 경로에 있는 파이썬 스크립트를 호출합니다. (`uv run ~/.gemini/config/skills/notion-uploader/scripts/upload_to_notion.py scratch/notion_upload_temp.md scratch/notion_upload_meta.json` - 실제 시스템 환경에 맞게 경로 동적 해석)
  - **성공 기준 및 예외 처리:** 터미널 명령어의 Exit Code가 0인지 확인하며, 에러 발생 시 출력된 STDERR 로그를 분석하여 원인을 파악합니다.
- **Step 3: 노션 API 통신 및 데이터 청킹 (결정론적 로직)**
  - **역할 주체:** 파이썬 스크립트 (`upload_to_notion.py`)
  - **로직 설명:** 
    1. 스크립트 상단에 PEP 723 규격으로 `notion-client` 및 마크다운 파서 라이브러리 선언.
    2. 로컬 프로젝트의 `.env`에서 `NOTION_API_KEY` 환경 변수를 로드.
    3. MD 파일을 노션 블록 객체로 파싱하며, 2,000자가 넘는 단일 텍스트는 안전하게 분할 처리.
    4. 최초 100개의 블록을 담아 `Mater DB(3bcbad03-...)`에 새 페이지 생성(POST) 요청.
    5. 남은 블록이 존재할 경우 100개 단위로 분할하여 `PATCH` 엔드포인트를 통해 페이지 하단에 이어붙임(Append).
  - **성공 기준 및 예외 처리:** HTTP 400 에러 시 블록 규격 문제로 간주해 일반 텍스트 포맷으로 Fallback 처리, HTTP 429 시 지수 백오프(Exponential Backoff)를 적용하여 재시도.
- **Step 4: 완료 보고 및 상태 정리 (Cleanup)**
  - **역할 주체:** 파이썬 스크립트 & 메인 에이전트
  - **로직 설명:** 파이썬 스크립트가 API 통신을 성공적으로 마치면 `os.remove()`를 호출하여 `scratch/` 내의 임시 파일 2개를 스스로 삭제하여 환경을 청소합니다. 메인 에이전트는 STDOUT으로 반환된 노션 페이지 URL을 수집하여 사용자에게 작업 완료를 최종 보고합니다.

      └── deploy-helper/                       # (예시) 다른 스킬 폴더들...

### 4.2. Agent Architecture (단일 vs 멀티)
- **에이전트 오케스트레이션:** **메인 에이전트 단독 수행.**
  - 선형적인 문서 변환 및 스크립트 호출 작업이므로 서브에이전트로 분할할 필요가 없습니다. 복잡하고 까다로운 노션 API와의 통신 및 분할 로직을 외부 파이썬 스크립트로 완벽하게 위임하였기 때문에, 메인 에이전트가 가벼운 상태로 글로벌 스킬을 단독 제어합니다.

### 4.3. Skills & Scripts
- **notion-uploader (SKILL.md):** 
  - 역할: 텍스트 산출물을 노션 데이터베이스에 업로드하는 글로벌 자동화 파이프라인.
  - 트리거: 사용자가 노션 업로드를 명시적으로 지시하거나, "결과를 노션에 정리해 줘" 등의 문맥 발생 시 작동.
  - 지침: 현재 작업 디렉토리의 `scratch/`에 임시 파일을 만들고, 글로벌 경로에 위치한 `upload_to_notion.py`를 `uv run`으로 실행할 것을 명시.

## 5. Tools, Integrations & DB (필요 도구 및 연동)
- **외부 연동:** Notion Public API
- **필수 환경 변수:** `.env` 내 `NOTION_API_KEY` (내부 통합 액세스 토큰 방식, 실행되는 대상 프로젝트 루트에 존재해야 함)
- **대상 DB 및 매핑 구조:**
  - DB ID: `3bcbad03-f76c-80c3-b81c-000b6bd3509a` ('Mater DB')
  - `Name` (title 속성): LLM이 동적으로 생성한 제목
  - `읽음상태` (select 또는 status 속성): "안읽음"
  - `구분` (select 속성): "AI 생성"

## 6. Edge Cases, State & Error Handling (상태 및 예외 처리)
- **상태 관리 (State/Memory):** 에이전트는 파일의 경로와 최종 생성된 노션 URL만을 단기 메모리로 유지하며, 작업이 끝난 후 임시 파일은 완벽히 파기합니다.
- **예외 시나리오 및 복구 로직:**
  - **환경 변수 누락:** `NOTION_API_KEY`가 작업 중인 프로젝트의 `.env`에 없을 경우, 스크립트가 즉시 실행을 중단하고 "현재 프로젝트 루트의 .env 파일에 NOTION_API_KEY를 설정해주세요."라는 메시지를 STDOUT으로 반환합니다.
  - **지원하지 않는 블록(Parsing Error):** 마크다운에서 노션 API가 호환하지 않는 태그 발견 시, 스크립트 단에서 에러를 던지지 않고 해당 부분을 일반 텍스트(Paragraph)로 강제 치환(Fallback)하여 데이터 유실을 100% 방지합니다.
  - **권한 오류 (HTTP 404):** 토큰이 일치하더라도 타겟 DB에 연결(Connection) 초대가 되어 있지 않아 발생하는 404 에러 시, "Mater DB 우측 상단 메뉴에서 API 통합(Integration)을 초대해주세요."라는 명확한 트러블슈팅 가이드를 터미널에 출력합니다.
